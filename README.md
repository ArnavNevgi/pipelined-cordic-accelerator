# Pipelined CORDIC Hardware Accelerator Benchmark

## Overview

This project implements a 16-stage pipelined CORDIC hardware accelerator in SystemVerilog for sine and cosine computation. The datapath uses rotation-mode CORDIC with signed Q2.14 fixed-point arithmetic and a valid-ready streaming interface with global-stall backpressure support.

The project was completed without a physical FPGA board. Correctness and implementation quality are demonstrated through Python golden-model generation, QuestaSim RTL simulation, randomized valid-ready testing, SystemVerilog assertion checks, RTL-versus-golden error analysis, latency and throughput benchmarking, and cross-vendor FPGA implementation on Vivado Artix-7 and Intel Quartus Cyclone V flows.

## Key Features

## Architecture

The CORDIC core tracks three signed fixed-point state values through the pipeline:

- `x`: accumulated cosine component
- `y`: accumulated sine component
- `z`: residual angle

Each pipeline stage performs one CORDIC micro-rotation using add/subtract and arithmetic right-shift operations. The design initializes `x` with the CORDIC gain compensation constant `CORDIC_K = 9949`, initializes `y` to zero, and loads `z` with the input angle.

The arctangent constants are precomputed in Q2.14 format and stored in `rtl/cordic_pkg.sv`. The lookup table values are generated by `scripts/gen_golden.py` and recorded in `reports/atan_table_q214.txt`.

The output mapping is direct:

```text
cos_out = x_pipe[STAGES]
sin_out = y_pipe[STAGES]
```

The core has 16 CORDIC iteration stages. Under continuous downstream readiness, the pipeline produces one sine/cosine output pair per cycle after the pipeline is filled. The measured first-output handshake latency in the current testbench is 17 cycles because the metric is measured from accepted input transaction to accepted output transaction.

## Fixed-Point Format

The design uses signed Q2.14 fixed-point arithmetic.

| Property | Value |
|---|---:|
| Total width | 16 bits |
| Fractional bits | 14 |
| Scale factor | 16384 |
| Approximate range | -2.0 to +1.9999 |
| Resolution | 0.00006103515625 |

Input angles are represented in radians using signed Q2.14 format. The supported input range for this implementation is:

```text
-pi/2 to +pi/2 radians
```

Sine and cosine outputs are also represented as signed Q2.14 values.

## Streaming Interface

The RTL uses a valid-ready streaming interface. It is not an AXI4-Stream interface; it is a compact project-specific handshake.

| Signal | Direction | Description |
|---|---|---|
| `clk` | input | Rising-edge clock |
| `rst_n` | input | Active-low reset |
| `in_valid` | input | Input angle is valid |
| `in_ready` | output | Core can accept an input angle |
| `angle_in` | input | Signed Q2.14 input angle in radians |
| `out_valid` | output | Output sine/cosine pair is valid |
| `out_ready` | input | Downstream sink can accept output |
| `sin_out` | output | Signed Q2.14 sine result |
| `cos_out` | output | Signed Q2.14 cosine result |

Backpressure is implemented with a global pipeline stall:

```text
pipe_advance = out_ready || !valid_pipe[STAGES]
in_ready     = pipe_advance
```

When the output stage contains valid data and `out_ready` is low, the entire pipeline holds its current state. This preserves the output sample and all in-flight transactions until the downstream interface accepts the result.

## Verification Methodology

The verification flow combines algorithmic reference generation, protocol stress testing, assertion checks, and numerical comparison.

The Python golden model generates directed and randomized Q2.14 input angles in the supported `-pi/2` to `+pi/2` range. It writes the testbench input vector file, the golden sine/cosine CSV, the arctangent lookup table report, and the generation summary.

The QuestaSim testbench reads `tb/cordic_test_vectors.hex`, drives the valid-ready interface, and captures RTL output into CSV files. It supports continuous streaming and randomized valid-ready stalls using plusargs. Randomized mode inserts input valid gaps and output backpressure while preserving source-side stability until handshake.

The comparison script checks RTL output ordering and signed Q2.14 values against the Python golden CSV. It reports maximum absolute error, mean absolute error, RMS error, and LSB error for sine and cosine.

SystemVerilog assertions in `tb/cordic_assertions.sv` check reset behavior, X-propagation, input stability while stalled, output stability during backpressure, and transaction-count ordering.

## Latency and Throughput Results

The benchmark flow measures throughput in continuous streaming and randomized backpressure modes.

| Benchmark | Output-span throughput |
|---|---:|
| Continuous streaming | 1.000000 outputs/cycle |
| Randomized backpressure | 0.713479 outputs/cycle |

The continuous result demonstrates one accepted output per cycle after pipeline fill. The randomized backpressure result is lower because the global-stall design intentionally preserves all pipeline state when the downstream sink deasserts `out_ready`.

Detailed benchmark results are stored in:

- `reports/benchmark_summary.md`
- `reports/benchmark_summary.txt`

## Limitations and Future Work

- The current input angle range is `-pi/2` to `+pi/2` radians.
- No physical FPGA board validation was performed.
- No board-level package pin constraints are included.
- Board-specific input/output delay constraints would be needed for hardware integration.
- Quadrant correction could extend the design to a wider angle range.
- An AXI4-Stream wrapper could be added around the existing valid-ready interface.
- A parameterized stage-count sweep could compare accuracy, latency, and utilization tradeoffs.
